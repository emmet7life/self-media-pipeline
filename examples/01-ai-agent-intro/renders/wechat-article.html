• 记忆：记住前面做了啥，别反复问同一个问题
  • 工具调用：能调 API、写文件、查数据库
  • DeepSeek-V3 / Qwen3-Max：开源替代，本地可部署
  • GPT-5.4-mini / Claude Haiku：轻量版，适合简单工具链

这里的关键是**描述**——LLM 靠描述来决定什么时候调这个工具。写得太抽象，它不知道怎么用；写得太长，它会忽略。

**最佳实践**：每个工具的描述包含三要素：何时用、参数是什么、返回什么。

## 第四步：串联起来

一个完整的 Agent 工作流就像生产线：

1. 接收用户输入
2. LLM 决定要不要调工具，调哪个
3. 执行工具，把结果塞回给 LLM
4. LLM 根据结果决定下一步：调下一个工具？还是输出最终答案？
5. 重复直到任务完成

这个循环就是 **ReAct（Reasoning + Acting）**。


## 常见坑

- **工具描述太抽象**：LLM 不知道何时该调，写清「何时用、用什么参数」
- **没有 fallback**：工具调用失败要优雅降级，而不是崩溃
- **上下文太长**：超过 100k token 后会丢早期信息，要加 summarization
- **工具太多**：一次给 Agent 20 个工具，它大概率选错。控制 <= 10 个

## 总结

Agent 不是更聪明的 chat。Agent 是**可执行的流程节点**。

入门路径很简单：选 LLM → 选框架 → 写工具描述 → 跑通第一个 ReAct 循环。

不要追求复杂。先让 Agent 做对一件事，再做更多。
